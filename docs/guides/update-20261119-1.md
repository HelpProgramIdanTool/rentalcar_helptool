копию с учётом работы Идана после предыдущего BACKUP SUCCESS.

Проверка 19.11: полный набор из 749 тестов прошёл. Отдельно проверен настоящий
серверный HTML с JS: календарь, значения калькулятора, выбор и сохранение,
вкладки и обычный выход. Свежий BACKUP SUCCESS подтверждён Иданом с удалённой

Выпуск подготовлен. Не считать установленным до журнала Render Live и проверки
версии. Нужна свежая копия с BACKUP SUCCESS; запуск команды или RETENTION COMPLETE
от предыдущего копирования сами по себе это не подтверждают.

1. Дождаться свежего `uv run python scripts/render_backup.py` → BACKUP SUCCESS.
2. Render → rentalcar-helptool → Manual Deploy → Deploy latest commit (main).
3. Проверить сборку, `partners.0006_test_workspace ... OK`, Live и 2026.11.19.1.
4. После Live заново открыть Render Shell нового экземпляра и выполнить:

```bash
uv run python manage.py create_partner_test --email idan.caliber@gmail.com
```

Она создаёт только отдельного ограниченного пользователя `idan-partner-test`,
не администратора. В Shell выводятся USERNAME, PASSWORD и URL. Пароль случайный,
не находится в Git и не выводится повторно. Не публиковать пароль и не присылать
его в чат. Если аккаунт уже существует, пароль сохраняется. Для осознанного сброса
есть отдельный флаг --reset-password. Команда не отправляет писем.

5. Открыть https://rentalcar-helptool.onrender.com/partners/workspace/ в отдельном
   профиле или окне инкогнито. Войти с выданными данными, чтобы не закрыть вход
   владельца в основной программе.
6. Для владельца: основной вход Идана →
   https://rentalcar-helptool.onrender.com/partners/workspace/owner/ → выбрать
   тестовый кабинет. Доступ разрешён только superuser; его учётная запись не
   заменяется учётной записью партнёра.
7. Проверить даты календарём, расчёт на будущие даты, сохранение оферты,
   повторный вход, тестовый заказ с инвойсом, список заказов и запрос изменения.
   Повторное создание того же выбранного заказа не должно давать дубль.
8. В /admin/partners/partnerworkspacerecord/ видны тестовые записи. Для проверки
   синхронизации Идан может поставить status CONFIRMED в тестовой записи.
9. Снять резервную копию после установки и проверки.

Тестовый режим отмечен в интерфейсе и проверяется сервером. Здесь сохраняются
данные в настоящей базе, но только в отдельных тестовых таблицах. Не создаются
обычные Booking/Customer/Quote-записи и не меняется статистика рабочих заказов.
Реальные письма фирмам, клиентам и владельцу из этого тестового кабинета пока
не отправляются. Проверка получателей и содержания сохраняется как симуляция.
Рабочая почта оператора остаётся по прежнему процессу.

Ограничения тестового выпуска: изменённые декларации и неподдерживаемые маршруты
передаются для ручной проверки; полноценное автоматическое оформление реальных
заказов и включение почты требуют следующего согласованного этапа. Исходный
макет в prototype остаётся только образцом; серверный интерфейс реализован в
приложении partners с настоящей проверкой прав и серверным калькулятором.
