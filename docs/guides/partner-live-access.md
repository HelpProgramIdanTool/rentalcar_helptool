# Рабочий и тестовый доступ партнёров

Основная программа владельца и кабинет партнёра используют одну базу, но разные
права. Партнёр не получает доступ к страницам оператора и видит только созданные
в своём кабинете записи. Создать доступ или изменить права может владелец.

## После установки 2026.11.20.3

В Render Shell создайте рабочего партнёра. Подставьте данные, которые владелец
получил от клиента; не сохраняйте их в публичном Git:

```bash
uv run python manage.py create_partner --email EMAIL --name "NAME" --owner-copy OWNER_EMAIL
```

По умолчанию логин — email. Команда напечатает пароль только при первом создании.
Сохраните его отдельно и передайте партнёру лично. Команда не отправляет письма
и не меняет цены/комиссии. Телефон можно добавить через `--phone` или в админке.
Режим цен выбирается отдельно в `PartnerAccess.pricing_sub_agent`, только если
такой режим уже применяется владельцем в ручных офертах.

Повтор команды не сбрасывает пароль. Для явного сброса добавьте
`--reset-password`. Команда откажется превращать обычного пользователя программы
в партнёра или менять тестовый режим существующего партнёра.

Вход: `/partners/login/`. После входа открывается `/partners/workspace/`.
Владелец может выбрать любой кабинет на `/partners/workspace/owner/`,
сохраняя вход в основную программу. Рабочие действия в выбранном рабочем
кабинете действительно отправляют письма; для экспериментов используйте тестовый.

## Отдельный тестовый вход Идана

Существующий логин `idan-partner-test` сохраняется. При необходимости создать
его или явно сбросить забытый пароль:

```bash
uv run python manage.py create_partner_test --email OWNER_EMAIL --reset-password
```

Тестовые записи не превращаются в рабочие заказы, не попадают в статистику
заказов и не отправляют письма. Чужие кабинеты этому логину недоступны — полный
доступ остаётся у основного аккаунта владельца.

## Отправка и заказы

Создание оферты показывает предосмотр и сохраняет её. Отправка — отдельная
кнопка: партнёру, по выбору также клиенту, с копией каждого письма владельцу.
Адрес копии берётся из настройки `workspace_copy_email`; при отсутствии адреса
рабочая оферта не создаётся. Письма помечены `[PARTNER · имя]`.

Выбранный вариант создаёт заказ в основной программе. Письмо направляется
поставщику с копией владельцу; состояние — ожидание подтверждения.
Подтверждение и номер резервации фирмы вносит владелец в основной программе,
после чего эти данные видны партнёру. Повторное нажатие не создаёт второй заказ.

Если почта не подтвердила отправку заказа, он остаётся в программе с отметкой
сбоя. Партнёр должен обратиться к владельцу, а не создавать повторную заявку.
Изменение или отмена — запрос владельцу. Заказ самостоятельно не изменяется.
