# Общее обновление 2026.11.14.1

Выпуск включает восемь пунктов из `docs/tasks/next-server-update.md`.
Серверная PostgreSQL остаётся рабочей базой. Локальную SQLite не загружать.

1. Перед развёртыванием выполнить в Render Shell:
   `uv run python scripts/render_backup.py`.
   Требуется итог `BACKUP SUCCESS` с проверкой удалённой копии.
2. Временно не создавать и не изменять заказы, не отправлять письма.
3. В Render выбрать Manual Deploy → Deploy latest commit. Сборка готовит
   переводы; существующая pre-deploy команда должна выполнить
   `uv run python manage.py migrate --noinput`.
4. Дождаться Live и проверить версию `2026.11.14.1` в меню программы.
   Проверить `uv run python manage.py showmigrations`: новые миграции отмечены `[X]`.
5. Проверить карточку существующего заказа, общий список клиентов и контактов,
   переключение RU / PL / EN. Убедиться, что имя арендатора и язык оферты не меняются.
6. Проверить расчёт CarFree: один город с разными пунктами, разные польские
   города на три дня и на четыре оплачиваемых дня. Программа берёт суммы из
   серверного тарифа; миграция их не заменяет. Если тариф отсутствует или истёк,
   сначала загрузить подтверждённый прайс, не подставлять придуманную цену.
7. Проверить CarFree Прага → Прага с выбранной Чехией и Прага ↔ Польша;
   другую фирму с выдачей за границей и только возвратом за границей.
   Чехия выбирается вручную. Зарубежные услуги без настроенной цены требуют проверки.
8. У MM Cars PREMIUM SUV должна остаться только категория среднего премиального
   SUV. Kaizen PFAH не должен появляться в новых расчётах. Не загружать поверх
   исправления старый `approved-mappings.json`: он содержит прежнюю ошибку.
9. Проверять новые письма только на собственном тестовом заказе и адресе.
   Никакие реальные заказы и ранее отправленные письма выпуск не пересылает.
10. После проверки выполнить новую резервную копию.

Контакты создаются на странице «Контакты обращений». В оферте и ручном заказе
поле «Кто обратился» по умолчанию означает самого клиента. Связь с контактом
сама по себе не включает комиссию. Период в статистике контактов относится
к дате создания, а отмены показываются отдельно от остальных заказов.

Прежние таблицы и исходные данные импорта не удаляются. При возврате старого
кода новые таблицы можно оставить; восстановление старой базы поверх новых
заказов не требуется. Если проблема связана с расчётом, остановить отправку
письма и проверить подробности, а не исправлять только его итоговый текст.
