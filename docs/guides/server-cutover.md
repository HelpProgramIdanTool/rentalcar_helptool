# Переход на сервер — состояние на 10.11.2026

Идан подтвердил завершение октябрьских сверок. Основной источник заказов до
переключения — локальная база программы. Общий рабочий файл —
`OneDrive/RentalCar/All_orders.xlsx`; отдельные таблицы по фирмам больше не ведём.
Excel обновляется по команде сверки, а не непрерывно.

Код и журнал версий сохраняются в Git. База, Excel, файлы клиентов, отчёты сверок
и секреты в публичный Git не попадают. Git не заменяет резервную копию данных.

## Что уже проверяли

- На Render работают приложение, PostgreSQL и постоянный диск.
- Есть отдельная тестовая база восстановления; она не должна заменять основную.
- Выполнялись проверка восстановления базы и отдельная проверка восстановления PDF.
- Сервер выгружает зашифрованные копии базы и вложений; проверялась обратная загрузка.
- Рабочая почта проверялась в режиме отправки только оператору.
- В программе есть обмен с общим Excel и дополнительный Excel-снимок в серверной копии.

Эти проверки относятся к предыдущему серверному состоянию. Они не означают,
что последние локальные заказы уже перенесены или что новые версии развёрнуты.

## Перед переключением

1. Развернуть сохранённую версию кода. Проверить версию и миграции на Render.
2. Проверить тариф и срок действия **основной** базы, место на диске и доступ владельца.
3. Подготовить и проверить процедуру импорта SQLite → PostgreSQL на отдельной копии.
   Она должна переносить пользователей, заказы, оферты, цены, сверки, историю,
   версии Excel и ссылки на вложения. Нельзя переносить только таблицу заказов.
4. На время окончательного экспорта прекратить запись в локальную программу.
   Сделать полную копию базы и файлов. Сохранить также текущую серверную базу.
5. Перенести данные и постоянные файлы по проверенной процедуре. Не затирать
   серверные настройки подключения, ключи и конфигурацию шифрования резервных копий.
6. Сравнить количество записей по всем переносимым таблицам, октябрьские итоги,
   новые и отменённые заказы, пользователей и контрольные суммы файлов.
7. На сервере проверить вход, создание/изменение/отмену заказа, получение вложения
   и тестовое письмо владельцу. Включение реальной рабочей почты — отдельный шаг:
   защитный режим `WORK_MAIL_MODE=test-only` пока не доказывает готовность реальной отправки.
8. Сделать резервную копию **уже перенесённых** данных и проверить её восстановление.
9. После проверки работать только на сервере. Локальную копию сохранить для возврата.
   Если после переключения на сервере появились новые заказы, нельзя просто начать
   писать в старую локальную копию: сначала нужно сохранить и вернуть новые данные.

## Общий Excel после перехода

Сервер не видит локальную папку OneDrive напрямую. Сохраняем рабочую процедуру:
закрыть Excel → загрузить актуальную книгу в «Синхронизация Excel» → проверить
различия → применить → скачать результат в ту же папку OneDrive.
Само наличие OneDrive на компьютере не настраивает серверную синхронизацию.

## Условие готовности

Переключение готово только после проверенного импорта, сверки данных, проверки
реальной почты и резервной копии перенесённых данных. До этого сервер подготовлен,
но актуальная рабочая база остаётся локальной.
