# Сверка: рабочий процесс владельца

Уточнено 03.11.2026 при сверке One Rent за октябрь. Это требования к дальнейшему
исправлению процесса, а не утверждение, что весь процесс уже автоматизирован.

1. Выбираем фирму и месяц.
2. Сохраняем копию полного файла владельца, не изменяя оригинал.
3. Сохраняем файл фирмы. Его состав определяет строки отчёта за месяц;
   дата аренды может относиться к предыдущему месяцу.
4. Сопоставляем фактуры фирмы с записями владельца. Имя и дата начала аренды
   могут быть основанием для предварительного сопоставления, но неоднозначность
   оставляем на проверке. Совпадение только email или только суммы недостаточно.
5. Только позднее получаем список работника — файлом или перечнем номеров.
   До этого принадлежность заказов работнику и его выплаты не определены.
6. После проверки фиксируем решения и отдельные фактуры/оплаты. Не выводим
   получение денег из наличия строки в отчёте или из результата сопоставления.

## Уроки формата One Rent Stepnet

- В полученном формате A — ID фактуры; B — время её выставления; C — номер
  фактуры; D — имя покупателя; E — начало аренды; F/G — брутто/нетто.
- Номера заказа в этом формате нет. A/C нельзя записывать в поле номера заказа.
- Нестандартное текстовое значение даты необходимо сохранять полностью.
- Несколько строк фирмы не обязательно дубли: сохранять отдельные фактуры,
  исходные строки и суммы. Повтор номера в другом месяце требует проверки:
  возможно дополнительное начисление, а не повтор всей аренды.
- Суммы фирмы и владельца хранить отдельно; расхождение не должно переписывать
  цену существующего заказа. Нетто берём из отчёта, если оно там явно указано.
- Итог всего отчёта фирмы должен быть виден до получения списка работника.
  Он не равен обороту заказов работника и не равен оплате нашей фактуры.
- Если номер есть в файле, но в базе его нет, сначала проверить возможный
  существующий заказ без номера. Не создавать повтор автоматически.
- Файл владельца может содержать многолетнюю историю и лист другой фирмы.
  Оригинал сохранять целиком; в текущую очередь выводить релевантные строки,
  не импортировать архив заново в качестве новых заказов.
- Отсутствие в файле фирмы не является подтверждением отмены.
- Прежние цветовые отметки сохранять как исходное свидетельство, не превращать
  автоматически в статус оплаты новой фактуры или отмену существующего заказа.

## Что ещё исправлять после разборов с владельцем

- Выбор профиля файла по заголовкам, а не одна фиксированная инструкция столбцов.
- Отдельные этапы загрузки и принадлежности работнику; не требовать работника заранее.
- Экран сравнения имени/даты/номера/сумм с доказательствами из обеих таблиц.
- Явное подтверждение совпадений, обработка нескольких фактур и корректировок.
- Удобный ввод перечня номеров работника без обязательного файла.
- Финальное оформление Excel и отметок после согласования спорных случаев.

Реальные исходники, промежуточные сравнения и резервные копии остаются в
приватных каталогах и базе. Клиентские данные не добавляются в репозиторий.
