Все 7 тестов затронутой группы после исправления прошли. Остальные 446 тестов
прошли в полном прогоне; повторный полный прогон после правок тестов не выполнялся.
`makemigrations --check --dry-run` — изменений схемы без миграций нет.

## Что есть сейчас

Программа работает локально на Windows: Python 3.12, Django, uv, SQLite.
Есть клиенты, заказы, подбор и расчёт предложений, письма на нескольких языках,
клонирование заказа, административная панель и новый модуль месячных сверок.
Последние изменения включают оформление оферт, польский текст, тему письма по
языку, детализацию стоимости и рейс в строке получения.

В модуле `reconciliation` реализованы загрузка своих Excel, отчёта поставщика
и списка работника; дополнение отсутствующих заказов; отмены и переносы;
расчёт комиссии; фактура и отдельные отметки поступления и выплаты денег;
версии результатов в Excel. Есть восстановление отметок прошлых месяцев и
блокировка повторного начисления. Руководство: `docs/guides/monthly-reconciliation.md`.

Модуль уже применялся локально к реальным сентябрьским данным трёх поставщиков.
Это не означает, что все спорные строки закрыты или платежи подтверждены.
Октябрьский отчёт поставщика ещё не получен. Производственной проверки на сервере нет.

## Подтверждённые Иданом правила бизнеса

- Сопоставление по поставщику и номеру заказа; отличия дат и сумм не мешают
  совпадению. Неоднозначные повторяющиеся номера требуют разбора.
- Один email может принадлежать организатору заказов разных водителей.
- Комиссия работника — 4% окончательной суммы нетто из отчёта поставщика,
  а не предварительной суммы из записей работника. НДС нужно подтверждать.
- Отсутствие заказа в отчёте не означает отмену. Возможен перенос на следующий месяц.
- У Kaizen есть прямые заказы с дополнительным номером W/H и соответствующим
  заказывающим юридическим лицом. По ним Идан получает отдельные 4%; это не
  комиссия работника. Другие юридические лица нельзя классифицировать автоматически.
- «Сверено», «поставщик оплатил фактуру» и «работнику выплачено» — разные состояния.
- Новая копия своих записей должна сохранять историю предыдущих сверок,
  не создавать дубликаты и позволять скачать Excel с прежними отметками.

## Финансовая модель: особенно просим проверить

Старый task 04 предлагал сначала обсудить модель денег с наставником.
Практическая работа пошла дальше: по прямым указаниям Идана модуль уже создан.
Нужна независимая оценка до дальнейшего расширения, а не предположение, что
прохождение тестов подтверждает правильность всей финансовой модели.

Проверьте `reconciliation/models.py`, `services.py`, `history.py`, `parsing.py`:

1. Разделение цены оферты, заказа и окончательных строк поставщика.
2. Округление нетто и комиссии: по строке или по общему итогу; кредитовые строки.
3. Историю исправлений, повторные месячные начисления и продления одной аренды.
   Сейчас повтор ранее учтённого номера блокируется; полноценного механизма
   последующей финансовой корректировки нет.
4. Допустимость статуса «учтён ранее» по принятой строке незакрытой сверки.
5. Идемпотентность загрузки, изменение исходного файла, неоднозначные номера,
   конкурентные действия двух сотрудников и границы транзакций.
6. Хранение Excel и JSON-снимков в базе, рост объёма, воспроизводимость итогов.
7. Текущие ограничения исправления оплаченной сверки и частичные платежи.

## План размещения — ещё не развёрнут

WordPress-сайты остаются на существующем Hostinger Business Web Hosting.
Для Django рассматривается отдельный Hostinger VPS KVM 2: 2 vCPU, 8 ГБ RAM,
100 ГБ диска. По сообщению поддержки заказ на первый год стоит $113.89;
оплата и активация Иданом ещё не подтверждены. Цена продления неизвестна.
Еженедельные копии включены, стоимость ежедневных не подтверждена.

Предложенная, но не реализованная схема: Django + PostgreSQL + Nginx/Caddy +
фоновый обработчик; Redis при необходимости. Docker Compose — вариант,
не принятое окончательное решение. Локальную модель ИИ запускать не планируем.
Альтернатива — управляемая платформа Render с большей регулярной стоимостью.

Требуется подготовить production-настройки: сейчас в `config/settings.py`
есть DEBUG=True, SQLite и ключ разработки в коде. Старый ключ нельзя использовать
на сервере; его значение здесь не приводится. Проверить также загрузку окружения,
разрешённые хосты, HTTPS, права, приватные файлы, журналирование и отправку писем.
Нужны миграция данных, тест восстановления резервной копии и план переключения
с локальной базы без потери последних изменений. Git не является копией базы.

## Следующий продуктовый этап — только предложение

1. Клиент открывает сохранённую оферту по защищённой ссылке из письма,
   выбирает вариант и подаёт заявку. У предложения есть срок действия и версия.
2. Общая заявка на несколько машин: общие контакты, рейс и адреса; отдельные
   водители, дополнительные услуги, цены и подтверждения для каждой машины.
3. Калькулятор доступен с WordPress и использует те же правила расчёта.
4. Управление доступностью по поставщику, категории, месту и периоду:
   автоматический расчёт / только запрос менеджеру / скрыть.
   Проверка также при возврате по старой ссылке и добавлении второй машины.
5. Без интеграции наличия поставщика заявка не считается подтверждённой арендой.
   При ограничении клиент явно отправляет запрос Идану для личной проверки.
6. Адаптация для телефона и планшета, затем PWA; автономная работа не согласована.
